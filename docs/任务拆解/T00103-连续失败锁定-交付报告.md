## 二、实现说明

- `MAX_FAILED_LOGIN_ATTEMPTS = 5`
- `LOCKOUT_MINUTES = 15`
- 锁定检查在 BCrypt 密码比对前执行。
- 第 5 次错误在同一次请求内写入 `failedLoginAttempts = 5` 和 `lockedUntil`，并立即返回 `423 Locked`。
- 锁定期内请求不执行密码校验，不增加次数，不延长 `lockedUntil`。
- 锁定期结束后，正确密码可以登录，成功路径会把失败次数重置为 `0` 并清空 `lockedUntil`。
- 连续失败被成功登录打断后，下一次错误从 `1` 重新计数。
- 锁定响应格式：

```json
{
  "error": "ACCOUNT_LOCKED",
  "lockedUntil": "2026-01-01T00:15"
}
```

## 三、技术选型核对

总体遵循任务说明：

4. 锁定使用 `423 Locked`，返回 `ACCOUNT_LOCKED` 和绝对 `lockedUntil` 时间。
5. 未修改 T00102 的 `USER_NOT_FOUND` / `INVALID_PASSWORD` 分支。

### SQLite 兼容性修正

任务说明建议使用：

```sql
ALTER TABLE "User" ADD COLUMN IF NOT EXISTS ...
```

实际运行 `mvn test` 时，当前 SQLite JDBC 版本报错：

```text
[SQLITE_ERROR] SQL error or missing database (near "EXISTS": syntax error)
```

该 SQLite 版本不支持 `ALTER TABLE ... ADD COLUMN IF NOT EXISTS`。因此采用等价且可执行的实现：

- 新建数据库时，直接在 `CREATE TABLE IF NOT EXISTS "User"` 中声明两个新字段。
- 已有旧数据库由 `UserRepository` 查询 `PRAGMA table_info("User")`，仅对缺失字段执行普通 `ALTER TABLE ... ADD COLUMN`。

这是为保留旧 T00101 数据库兼容性而做的实现细节偏离；锁定业务规则和数据字段未改变。

## 四、新增测试用例

`AuthIntegrationTest.java` 使用固定 `Clock`，共新增/覆盖以下规则：

1. `fifthWrongPasswordLocksAccountAndReturns423`
   - 前 4 次错误返回 401。
   - 第 5 次错误返回 423 + `ACCOUNT_LOCKED`。
   - `lockedUntil` 约为当前时间 + 15 分钟。
   - 数据库失败次数为 5。

2. `lockedAccountRejectsLaterRequestsWithoutChangingLockTime`
   - 锁定后第 6 次请求仍返回 423。
   - 使用正确密码也不会绕过锁定。
   - `lockedUntil` 不变，失败次数不继续增加。

3. `correctPasswordAfterLockExpiresLogsInAndClearsFailures`
   - 固定时钟推进 15 分钟。
   - 正确密码重新登录成功。
   - 失败次数归零，`lockedUntil` 清空。

4. `successfulLoginResetsConsecutiveFailuresBeforeNextFailure`
   - 连续错误 2 次后成功登录。
   - 成功后再次错误只记录为第 1 次。

原有 T00101/T00102 测试也继续保留：成功登录、Session 过期时间、账号不存在、密码错误、feature flag 关闭等测试均通过。
