### 完成定义（DoD）
- 默认展示全部todo

- 点击"已完成"只展示`completed === true`的todo

## T-UI-02：Todo创建时间相对化展示

你要做的事：把Todo条目当前固定文案"待处理"替换/补充为基于`createdAt`的相对时间展示（如"3分钟前"）。
对应验收标准：无新增AC；验收要点：新创建的todo展示合理的相对时间文案。

本任务信息自包含：不要假设除下文之外还有更多规划背景，下面就是执行这个任务所需的全部上下文。

### 背景
`Todo`类型当前定义为`{ id: number; title: string; completed: boolean }`，**不含`createdAt`字段**——`[FACT]`自查确认后端`Todo` record确实有`createdAt`，但前端`Todo`类型定义未声明该字段，`fetch('/api/todos')`拿到的JSON其实包含`createdAt`，只是前端类型和渲染都没用到。渲染处当前固定写死`<small>待处理</small>`。

### 预计涉及文件

**必须改动**：
- `client/src/App.tsx`（修改：`Todo`类型新增`createdAt: string`字段；新增相对时间计算函数；渲染处替换固定文案）

**可能改动**：无。

### 技术选型
**相对时间计算方式** → 不引入`date-fns`/`dayjs`等日期库，手写最小实现：`(Date.now() - new Date(createdAt).getTime())`算毫秒差，按阈值分档（<1分钟"刚刚"，<60分钟"X分钟前"，<24小时"X小时前"，否则显示日期`YYYY-MM-DD`）。依据：仓库当前`package.json`无任何日期处理依赖，为单一展示需求新增外部库属于过度设计。`[ASSUME]`

**是否自动刷新** → 不用`setInterval`定时重算，只在组件因其他状态变化重渲染时才重新计算相对时间（如新增/筛选todo时顺带更新）。依据：AC未要求"页面停留期间数值自动跳字"，加定时器是本任务未被要求的额外复杂度。`[ASSUME]`，如产品需要精确到秒级自动刷新，需另提需求。

### 你要做什么
1. `Todo`类型补充`createdAt: string`字段
2. 新增一个纯函数（如`formatRelativeTime(createdAt: string): string`），按上述档位计算
3. 渲染处把`<small>待处理</small>`替换为`<small>{formatRelativeTime(todo.createdAt)}</small>`（如果"待处理"本身还有其他语义用途，可以在时间文案基础上保留，`[ASSUME]`按替换处理，因为该文案当前看不出除占位以外的实际用途）

### 从验收标准推导出的隐含规则
无（两条技术选型里的假设已覆盖模糊点，不重复列为隐含规则）。

### 明确不要做的事
- 不要引入新的日期处理依赖
- 不要新增自动刷新定时器
- 不要修改后端返回的`createdAt`字段格式

### 完成定义（DoD）
- 新创建的todo展示"刚刚"
- 有单元测试覆盖`formatRelativeTime`函数至少3个档位（刚刚/X分钟前/X小时前）的正确性
- `npm run typecheck`通过（新增`createdAt`字段不破坏现有类型）

**CI/CD验收模式：PR-only**

### 假设与待确认项
- `[ASSUME]` 相对时间不自动刷新，只在组件重渲染时重算；`[ASSUME]` 不引入日期库，手写最小实现——两者材料均未明确规定，如产品有更精确要求需另行反馈。

### 你要做什么

- 不要修改后端任何逻辑

- 登录成功后，`localStorage`中存在记住的用户名，值与刚提交的一致
- 重新挂载`LoginForm`组件（模拟刷新页面），用户名输入框自动填充为上次记住的值
