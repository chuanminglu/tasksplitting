## 1. 任务理解（AC 拆解）

AC-3 实际包含**两条独立断言**：
1. **旧密码登录失效** —— 这条由 T00202 把 `User.passwordHash` 换成新 BCrypt 哈希天然满足（旧密码校验时 `BCryptPasswordEncoder.matches` 直接失败）。
2. **旧会话立即失效** —— 这条**未被 T00202 覆盖**，必须在 T00203 显式补上：密码重置成功后，该用户所有 `Session` 行被删除，旧 bearer token 访问任何受保护接口都会被 `AuthInterceptor` 拒绝（401）。

Spec 的 `[INFER]` 段明确警告："这两者是同一条 AC 里的两个独立断言，容易被误认为 T00202 已经顺带做完，需要在本任务里显式补上会话失效这部分，不能假设它已经被覆盖。"本任务严格遵循。

## 3. 关键技术决策

1. **`deleteAllForUser` 严格限定 userId**：`WHERE userId = ?` 单值参数绑定，不传其他条件，从 SQL 层保证**不影响其他用户的 Session**。DoD 边界用例 `otherUserSessionUnaffectedByReset` 显式验证。
2. **调用位置**：`resetPassword` 在 `markUsed` **之后**、`log.info` **之前**调用 `deleteAllForUser`。顺序原因：先完成密码更新 + 验证码标记（既有 T00202 语义），再做 T00203 新增的会话失效——避免把会话失效逻辑混进 T00202 已验证过的路径中间。
3. **事务边界**：Spring 默认 JdbcTemplate 操作各自独立事务（非 `@Transactional`）。`deleteAllForUser` 与 `updatePasswordHash`、`markUsed` 在同一方法内顺序调用；若 `deleteAllForUser` 抛异常，密码/验证码已落库但会话未删——这是可接受的"弱一致性"，与 T00202 的既有行为一致（本任务 spec 未要求事务原子性）。
4. **测试隔离**：独立 SQLite 文件 `target/test-t00203.db`（沿用 T00202 模式），`@BeforeAll` 删文件、`@BeforeEach` 清空 `PasswordResetCode/Session/LoginEvent/User/Todo` 5 张表 + `testClock.reset()`，与其他集成测试完全隔离。
5. **受保护接口选择**：`GET /api/todos`（`WebConfig` 明确该路径受 `AuthInterceptor` 保护，`AuthInterceptor.preHandle` 在 `SessionRepository.findByToken` 找不到 token 时返回 401 `{"error":{"code":"UNAUTHORIZED",...}}`）。
6. **会话失效验证方式**：
   - **HTTP 层**：重置前 `GET /api/todos` 携带旧 token → 200；重置后同 token → 401 `UNAUTHORIZED`。
   - **DB 层**：`SELECT COUNT(*) FROM "Session" WHERE token = ?` → 0（直接证明 token 已被 `deleteAllForUser` 删除）。
   - **边界**：user2 的 Session 行数仍 = 1，user2 token 仍可访问 `/api/todos` → 200。

## 5. 风险与限制

1. **`Session` 表无 `id` 列**：spec 中"预计涉及文件"未涉及，但写测试时踩到——`Session` 主键是 `token`（TEXT），不是自增 `id`。测试 seed 用 `INSERT INTO "Session" (token, userId, expiresAt)` 不传 id，与 `SessionRepository.create` 完全对齐。
2. **`@MockBean` 已标记过时**：Spring Boot 3.4 中 `@MockBean` 仍可用但标记 `@Deprecated`（日志 WARN）。沿用 T00201/T00202 既有模式（项目内统一），未在 T00203 单独升级。
3. **事务原子性**：见第 3 节决策 3。若 `deleteAllForUser` 抛异常（如 SQLite 锁），密码已更新但会话未删——理论上用户可用旧 token 访问新密码下的受保护接口**一次**（下一次请求时 token 已被删或下次启动时被清理）。本任务 spec 未要求 `@Transactional`，与 T00202 的既有行为一致，不扩大范围。
4. **测试未覆盖**：并发场景（同一用户同时发起两次重置）未测——spec 未要求，超出 DoD 范围。
