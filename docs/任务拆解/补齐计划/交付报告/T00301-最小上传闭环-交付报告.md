## 3. 实现要点与关键决策

1. **落盘策略**:文件名统一 `UUID.randomUUID() + "." + ext`(保留原始扩展名用于 Content-Type 映射),避免路径穿越与重名覆盖;目录由 `@Value("${avatar.upload-dir:uploads/avatars}")` 配置,默认 `server/uploads/avatars`。
2. **数据库演进**:`sql.init.mode=always` 导致 `schema.sql` 每次启动重放,故**不**把裸 `ALTER TABLE ADD COLUMN` 写进 `schema.sql`,而是在 `UserRepository` 构造期用 `PRAGMA table_info("User")` 探测列是否存在,缺失才执行 `ALTER TABLE ... ADD COLUMN avatarUrl TEXT`——幂等且对旧库平滑升级。
3. **鉴权贯通**:`/api/avatars` 纳入 `AuthInterceptor` 拦截路径;`POST` 通过 `@RequestAttribute("userId")` 拿到当前会话用户,`GET` 回读为公开静态资源(不强制鉴权,便于 `<img>` 直接加载)。
4. **多部分请求契约**:前端 `fetch` 上传使用 `FormData` 且**不手动设置 `Content-Type`**(交由浏览器生成 boundary);测试断言 `Content-Type` 未手动设置,确保真实 multipart 语义。
5. **占位头像**:无头像时展示内联 SVG data-URI(中性灰色人形剪影),不发起额外请求。
