## 一、任务概述

按候选故事-忘记密码与头像上传 执行计划 T00202（AC-2）：新增 `POST /api/auth/reset-password` 接口——请求体 `{"email": "...", "code": "...", "newPassword": "..."}`。

- **验证码在有效期内且正确且未使用** → 用 `BCryptPasswordEncoder` 哈希 `newPassword` 更新 `User.passwordHash`，并标记该验证码 `used=TRUE` → **200 + 成功文案**。
- **查不到 / `used=TRUE` / 已过期（`expiresAt` 早于当前时刻；恰好等于不算过期，与 T00103/T00106 一致）** → 抛 `AuthException`（`code = "INVALID_OR_EXPIRED_CODE"`），拒绝，密码不变。

复用 T00201 已落地的真实签名：`PasswordResetCodeRepository.findByEmailAndCode(email, code)` → `Optional<PasswordResetCode>`（record 含 `id` 字段，用于按 id 标记 used）、`UserRepository.findByEmail(email)`。

## 三、技术选型与方案一致性

- **复用 `AuthException` 模式**：spec 要求"复用 `AuthException` 模式，`code = "INVALID_OR_EXPIRED_CODE"`"。`AuthException(code, message)` 构造 + `@ExceptionHandler` 映射为 401 + `{error:{code,message}}`，与 `AuthController` 的非锁定分支完全一致。✅
- **BCrypt 哈希**：`new BCryptPasswordEncoder()`（同 `AuthService:24`），`encode(newPassword)` 写库、测试用 `matches(newPassword, newHash)` 断言。✅
- **过期边界**：`record.expiresAt().isBefore(LocalDateTime.now(clock))`——**恰好等于不算过期**（`isBefore` 严格小于），与 T00103/T00106 约定一致；用 `TestClock` 精确覆盖"恰好等于仍有效"边界。✅
- **时间源可注入**：沿用 `ForgotPasswordService` 已注入的 `Clock`（`now(clock)`）。✅
- **一次性使用**：校验通过后 `markUsed(id)`，`used` 置 `TRUE`，再次提交同码命中 `record.used()` 分支被拒（[INFER] DoD）。✅
- **安全**：拒绝时不改密码、不标记 used；响应体只含成功文案，不泄漏验证码/注册状态。✅
