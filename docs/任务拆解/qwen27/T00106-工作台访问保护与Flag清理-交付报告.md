## 二、实际技术选型

与任务说明一致：

- 鉴权方案沿用 T00101 已建立的 `Session` 表 + token 方案，不引入新依赖。
- 拦截器使用 Spring MVC `HandlerInterceptor`（项目未启用 Spring Security 全家桶，`spring-security-crypto` 仅提供 BCrypt），路径模式 `/api/todos/**` 与 `TodoController` 路由精确对齐。
- token 校验顺序：先解析 header（缺失/格式错误），再查库（不存在/过期），两步失败分别返回不同 `message`，`code` 统一 `UNAUTHORIZED`，与登录端点错误结构一致。
- 前端不做路由守卫：`App.tsx` 已有的 `token === null ? <LoginForm/> : <TodoBoard/>` 分支即登录态门控；工作台所有数据请求统一携带 Bearer，任一 401 触发 `onLogout()`，用户回到登录页。
- 时钟仍用 T00103 注入的 `@Bean Clock`；`AuthInterceptor` 通过构造器拿到同一 bean，测试中 `TestClock` 以 `@Primary` 覆盖，`advance()` 驱动过期用例。

## 三、新增测试用例

### 后端 — `/api/todos` 全量鉴权（`TodoAuthIntegrationTest`）

独立 Spring 上下文，独立 SQLite 库 `target/test-todo-auth.db`：

1. `getTodosWithoutTokenReturns401`：无 Authorization header → 401 + `error.code = UNAUTHORIZED`。
2. `postTodosWithoutTokenReturns401`：无 token 创建 todo → 401，不落库。
3. `getTodosWithValidTokenReturns200`：先 `POST /api/auth/login` 取 token，再带 Bearer `GET /api/todos` → 200 + 数组。
4. `postTodosWithValidTokenReturns201`：带有效 token 创建 → 201 + 回显 `id/title/completed/createdAt`。
5. `getTodosWithExpiredTokenReturns401`：直接更新 `Session.expiresAt` 到过去，再带 token 请求 → 401。
6. `getTodosWithUnknownTokenReturns401`：伪造不存在的 token → 401。
