## 三、实际技术选型是否与说明一致

**8 项技术选型全部按说明落地**：

1. **数据库 schema 管理** — ✅ `schema.sql`（`CREATE TABLE IF NOT EXISTS`）+ `spring.sql.init.mode: always`，未引入 Flyway
2. **密码哈希** — ✅ 仅 `spring-security-crypto` 的 `BCryptPasswordEncoder`，未引入完整 `spring-boot-starter-security`
3. **会话凭证载体** — ✅ 自建 `Session` 表（`token` 主键 / `userId` / `expiresAt` / `createdAt`），`UUID.randomUUID().toString()` 不透明 token，无 JWT
4. **是否引入 Service 层** — ✅ 引入 `AuthService`，`AuthController` 只做 HTTP 层转换
5. **Feature Flag 实现** — ✅ `application.yml` 新增 `app.feature.login-auth-enabled: false`，`@Value` 直接注入
6. **Flag 关闭时的接口行为** — ✅ 返回 `404 Not Found`
7. **时间可测试性** — ✅ `AuthService` 注入 `Clock`，通过 `LocalDateTime.now(clock)` 取时间
8. **测试用户数据来源** — ✅ 不新增 `data.sql`，集成测试内部直接调用 `UserRepository.create` 播种

**实现细节偏离**（一处，属落地细节而非选型变更）：
- `SessionRepository` 写入侧将 `expiresAt` 格式化为 `yyyy-MM-dd HH:mm:ss` 字符串。原因：SQLite JDBC 的日期解析器只接受"空格分隔"格式（`CURRENT_TIMESTAMP` 产出的形态），直接绑定 `LocalDateTime` 会写入 ISO-8601（`T` 分隔），回读时其自带日期解析器无法识别。这是在保留选型（`LocalDateTime` 参数、`JdbcTemplate` 手写 SQL）的前提下让"Session 表 `expiresAt` 可被回读断言"的 DoD 可执行的最小实现细节。
