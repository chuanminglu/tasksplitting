## 🛠️ 关键技术细节

### 后端架构

```
src/
├── auth/
│   ├── loginController.ts    (6处埋点接入)
│   ├── token.ts              (可配置expiresIn)
│   ├── password.ts           (bcrypt)
│   └── errors.ts             (4种错误码+ACCOUNT_LOCKED)
├── config/
│   └── featureFlags.ts       (flag读取逻辑)
├── tracking/
│   └── authEvents.ts         (埋点定义+全局上报器)
└── routes/
    └── auth.ts               (POST /api/auth/login)
```

### 前端架构

```
frontend/src/
├── pages/
│   └── Login.tsx             (表单+错误展示)
├── api/
│   └── auth.ts               (API调用)
└── utils/
    └── tokenStorage.ts       (localStorage/sessionStorage切换)
```

### Token设计

```
Header.Payload.Signature (HMAC-SHA256)

Payload:
{
  "sub": "user-id",
  "username": "username",
  "iat": 1694956800,           // 秒为单位
  "exp": 1694960400            // iat + expiresIn
}

expiresIn:
- rememberMe=true:  604800秒   (7天)
- rememberMe=false: 7200秒     (2小时，默认)
```

## 💡 方法论评价

### 简报模板的有效性

**"切片任务简报"的关键要素** ✅

1. **背景段** — 交代前置状态，agent无需猜测
2. **预计涉及文件** — 帮助规划和检查范围
3. **你要做什么** — 具体、可执行的任务描述
4. **明确不要做的事** — 防止scope creep
5. **完成定义** — 清晰的验收标准
6. **交付要求** — 包括与预计文件的核对

**这套模板的稳定性** ✅

- 5个切片全部成功交付，无返工
- 预计文件命中率平均100%(按实际需要修改的文件)
- 每个切片的agent都能独立理解需求，无歧义

### 关键改进建议

#### 1️⃣ 埋点体系的前向设计
在切片1-2的规划阶段，就明确"埋点是后端驱动还是前端驱动"，可以避免切片5时的设计反复。

#### 2️⃣ "预计文件"的精度分级
区分"必须改"和"可能改(依赖决策)"：
```
必须改: loginController.ts, authEvents.ts
可能改: Login.tsx (依赖埋点架构决策)
```

#### 3️⃣ 验收清单的模板化
本项目的PREFLIGHT-CHECKLIST可作为后续埋点接入切片的标准模板。

#### 4️⃣ "测试用例 ↔ AC"的显式追踪
建立映射表便于维护：
```
AC-1 → test/auth/login.test.ts:78-95
AC-2 → test/auth/login.test.ts:98-210
AC-3 → test/auth/login.test.ts:265-355
AC-4 → test/auth/login.test.ts:415-490
AC-5 → 上述所有测试的埋点验证部分
```

#### 5️⃣ 切片间的隐式依赖显式标注
```
切片1: 无依赖 → 提供给2,3,4,5
切片2: 依赖1 → 提供给3,4,5
切片5: 依赖1-4 → 最后一片
```
